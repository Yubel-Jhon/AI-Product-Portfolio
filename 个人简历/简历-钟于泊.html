① AI Agent 行业情报 Skill

独立开发 · 每日运行 · 开源
Yubel-Jhon/Daily-Briefing-on-the-AI-Agent-Industry · 纯 Python 标准库，零第三方依赖

AI Agent 赛道迭代快，情报散在 changelog、GitHub、公众号等渠道，人工盯 12 家厂商不现实。把这件事做成一个每日自动运行的 Skill 智能体，持续产出可采信的结构化情报。

  • 产品定义与信息架构：主导 0→1，定义触发条件、执行步骤与输出规范。竞品认知分两层管：「已知事实」（定位、开源、模型）季度核对一次，「变化信息」（定价、迭代、融资）每次刷新，日常迭代只动第二层，维护成本压到可日常运行
  • 自动化流水线与能力拆分：独立搭建采集、解析、核验、diff、推送的全流程，盯字节、阿里、腾讯、百度、月之暗面等 12 家厂商。按单一职责拆成 fetch（脚本）、verify（脚本 + LLM）、update（LLM）、notify（可选）四块；纯 Python 标准库 + gh CLI，零第三方依赖，换台机器就能跑
  • 可信度与边界设计：国内大厂多数不公开 changelog，部分站点抓取被网络策略拦截。据此设计两档可信度评级（谁在说、有无第二家来源），源注册表里标明哪些渠道有盲区；读不到原文就标注读不到，不编造

② 商品企划生成 Agent

独立开发 · 开源
Yubel-Jhon/Accessory-Merchandising-Planning- · 2026-09 最新迭代

传统服饰商品企划靠企划师个人经验：选品逻辑、对标方案、企划 deck 都要人工逐个做。做一个端到端的生成 Agent，输入一张产品图，输出一份能直接汇报的企划 deck。

  • 产品架构设计：流程分三段：起盘选一张产品图；转换阶段用通义 qwen-image-3.0-pro 批量生成 7 类视觉方案，点选定稿；组装阶段自动产出 6 段选品逻辑与商品编排，一键导出 PPT/HTML。从图到 deck 一条线跑通
  • 领域数据资产建设：自建 3 方向 × 4 品类中英双语选品库，以及图类型 prompt、零售商风格、对标库。Agent 生成选品逻辑和出图 prompt 都从这里取材，输出贴近真实商品企划的工作语言
  • 工程落地与可用性：Flask 后端（生图 / 导出 API）+ pywebview 桌面端，双击启动脚本自动装依赖、开浏览器，零配置可用；关闭 prompt_extend 后单张出图 20–60s（提速约 20 倍），API Key 自动读取，演示走「载入示例 → 出图定稿 → 导出企划」最短路径

③ 动漫数字人直播系统

全流程落地 · 开源
Yubel-Jhon/Anime-Digital-Human · 潮玩盲盒带货场景

潮玩盲盒直播间靠真人主播，时长和人力成本都受限。做一个能 7×24 在播的动漫数字人：观众弹幕要能实时答，商品信息不能瞎编，口播还要对上嘴型。

  • 场景定义与指标设计：只定两条硬指标：知识库命中率 ≥90%（不瞎编）、端到端延迟 ≤10s（能实时答），之后的架构与成本取舍全部对着这两条来
  • 系统架构与技术选型：设计「弹幕接入 → RAG 检索 → LLM 生成 → TTS → 嘴型驱动」全链路。命中知识库直接照抄标准答案，从根上防幻觉；没命中走 DeepSeek 生成；没有 API Key 就自动降级到 FAQ 标准答案，直播间不下线。GPU 推理放远端，本地只做编排
  • 性能调优与迭代：前后换了 5 版技术路线，从 SadTalker 视频、Live2D 实时到 mod 化和 Electron 桌面包。BGE 模型预热把首答延迟从 11s 降到 3.7s，进入 ≤10s 指标以内
  • 交付与文档：4 条嘴型同步 demo 视频（价格、正品、隐藏款、发货问答），MRD/PRD 与踩坑复盘全部开源；密钥走 .env，不进仓库
