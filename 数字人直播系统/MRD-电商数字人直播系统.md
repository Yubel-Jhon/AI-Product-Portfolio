## 2. 背景与问题

### 2.1 为什么是电商数字人

- 直播电商是中小商家获客/成交主渠道，但「人」是最大瓶颈：成熟主播月薪 8K-30K + 提成，中小商家养不起、留不住
- 真人直播顶多 8 小时，凌晨/长尾流量无人承接
- 现有数字人方案两极分化：大厂（硅基/魔珐/京东言犀）5-10 万/年起只服务大客户；开源方案（HeyGem/Linly-Talker）技术强但裸代码无产品化，个人不会用
- **中间空白**：「低价、轻量、个人可做、开箱即用」的数字人，没人做

### 2.2 我要解决的问题

1. 数字人「一问三不知」——观众问尺码/发货/保质期没人答（调研：观众第一痛点是交互，而非像不像真人）
2. 数字人「千篇一律」——没有记忆点，停留短
3. 数字人「贵且重」——个人做不动，需要一条轻量路线

## 3. 目标市场与用户

### 3.1 目标场景

| 维度 | 定义 |
|---|---|
| 场景 | 中小商家无人/半无人直播带货 |
| 平台 | 抖音（先单平台，单一垂类） |
| 垂类 | 潮玩（手办 / 盲盒 / 谷子） |
| 形态 | 轻量数字人（单机本地、动漫为主） |

### 3.2 服务对象（这个数字人替谁干活）

> 💡 虽是个人作品，但数字人必须有明确的「替谁解决什么问题」，否则作品就是无源之水。

| 画像 | 痛点 | 我的数字人怎么解 |
|---|---|---|
| 个人店主（请不起主播） | 想开直播没人播 | 7×24 挂机替代真人 |
| 小品牌运营（矩阵开播） | 真人主播不够用 | 低成本批量开播 |
| 个人创业者（不想露脸） | 没时间/不想露脸 | 数字人代播 |

### 3.3 观众侧痛点（决定数字人有没有用）

> 💡 排序依据调研：**交互智能 > 信任 > 拟真度**。观众最在意的不是「像不像真人」，而是「我问的问题有没有被回答」。

| 优先级 | 痛点 | 我的解法 |
|---|---|---|
| P0 | 问问题没人答 | LLM + 商品知识库实时应答 |
| P0 | 不信任（怕 AI 骗人/录播） | 写实形象 + 口型 + 实时交互建立信任 |
| P1 | 拟真差（口型对不上） | 口型驱动（Wav2Lip） |
| P2 | 同质化没记忆点 | 动漫形象差异化引流 |

## 4. 竞品分析

### 4.1 竞品格局

| 竞品 | 形态 | 优势 | 劣势 |
|---|---|---|---|
| 硅基智能 / 魔珐 / 京东言犀 | 大厂定制 | 拟真高、案例多 | 贵（5-10万/年）、千人一面 |
| HeyGem / Linly-Talker | 开源裸代码 | 免费、技术强 | 无产品化，个人不会用 |
| HeyGen（海外） | 视频生成 SaaS | 拟真顶级 | 按分钟计费、非直播实时 |
| 录播视频 | 低成本 | 极便宜 | 无交互、易限流 |

### 4.2 差异化定位

> 💡 **差异化关键**：不拼拟真度（拼不过 HeyGen/大厂），不拼技术深度（拼不过开源社区）。个人真正的优势在**内容策略 + 轻量落地**——把「动漫引流 + 写实成交」这个打法，做成一个个人能跑起来的轻量数字人。

| 维度 | 差异化方向 |
|---|---|
| 形象 | **动漫为主**（高辨识度、避恐怖谷、算法友好、且轻量），写实为辅（成交信任） |
| 交互 | LLM + 知识库实时应答，解决「一问三不知」 |
| 轻量 | 单机本地、开源组装、个人可控，不依赖云 GPU |
| 内容 | 话术/知识库/双形象打法是持续积累的护城河 |

**为什么「动漫 + 轻量」对个人成立（逻辑自洽）**：动漫（Live2D，2D）比写实（口型驱动 + 高保真渲染）轻一个量级，个人机器扛得住；写实拼不过大厂 DiT，那就让写实当「信任补充」，动漫当「差异化 + 性能」主力。

## 5. 产品定义

> 💡 这里是本 MRD 的核心产出——把「轻量数字人」的边界说清楚。

### 5.1 一句话定义

一个**单机本地跑、动漫形象为主、能直播带货、能实时回评论**的轻量数字人。

### 5.2 能力边界（做什么 / 不做什么）

| 做（MVP） | 不做（明确砍掉） |
|---|---|
| 动漫形象 + 写实形象双形象 | 自定义 3D 形象建模 |
| 口型驱动（Wav2Lip） | 端到端 DiT 高保真生成 |
| 声音合成（GPT-SoVITS） | 实时语音克隆训练重活 |
| LLM + 知识库实时评论应答 | 多平台矩阵 |
| 单一垂类、单一平台（抖音） | 智能选品/定价 |
| AI 标识 + 真人接管（合规） | 商业化 SaaS / 多租户 |

### 5.3 个人可控三层（我的主战场）

| 层 | 内容 | 说明 |
|---|---|---|
| 配置层 | 形象/声音/话术/脚本/知识库 | 产品化封装，非技术也能配 |
| 内容层 | 话术模板、知识库、问答设计 | 我的差异化积累 |
| 运营层 | 排期开播、复盘、调优 | 跑出效果证明价值 |

## 6. 关键假设与风险

### 6.1 需验证的关键假设

| 编号 | 假设 | 验证方式 |
|---|---|---|
| H1 | 动漫形象 + 实时交互，能让数字人直播「跑得起来且比录播有用」 | 自己搭起来实测，对比无交互录播 |
| H2 | 本地轻量技术栈（小模型 LLM + Wav2Lip + GPT-SoVITS）串成低延迟链路 | PoC：评论进来 10s 内口播回答 |
| H3 | 知识库 RAG 约束下，应答准确率够用（不胡编） | 评测集测命中率/事实忠实度 |
| H4 | 动漫差异化确实带来「记忆点 + 停留」 | 对比纯写实数字人 |

### 6.2 Top 风险及应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 平台限制数字人无人直播 | 致命 | 内置 AI 标识 + 真人接管，走「半无人」 |
| 本地链路延迟高、观感差 | 高 | 预生成 + 缓存，Wav2Lip 轻量优先 |
| LLM 答错商品信息 | 高 | RAG 强约束，事实字段取商品库，不编造 |
| 个人时间/精力有限 | 中 | 锁单一垂类、单一平台，控制范围 |

## 7. 结论

| 评估维度 | 结论 |
|---|---|
| 方向 | 电商数字人需求真实、中间空白存在 |

| 可行性 | 技术栈开源可组装，无需自研模型 |
| 个人匹配 | 轻量路线贴合个人能力，非重资产 |
