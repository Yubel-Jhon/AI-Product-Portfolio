# 动漫数字人直播系统 · 设计文档

> 状态：待 review　|　日期：2026-08-29　|　用途：面试作品集（demo 演示，非商用运营）

## 1. 背景与目标

**做什么**：一个「有主播感」的动漫数字人，在 B 站直播间实时响应观众——回答问题、点名互动、表情反应、主动引导。

**为什么做**：面试作品集，展示一套完整的「弹幕 → AI 大脑 → 语音 → 数字人形象 → 推流」实时系统。

**核心指标**（沿用早期复盘定下的目标）：
- 能实时答：端到端延迟 ≤10s（评论 → 开始出声）
- 不瞎编：知识库命中时照抄标准答案，未命中时明确「不知道」，不编造事实

**当前基础**：已跑通「音频闭环」（`kb.py` RAG + DeepSeek + `edge-tts`）。SadTalker 嘴型线已打通但效果差、且非实时（8s 音频约 90s），本方案弃用。

## 2. 需求（已与用户逐项对齐）

| 维度 | 决定 |
|---|---|
| 技术路线 | Live2D（CPU 渲染，**不租 GPU**） |
| 平台 | B 站 |
| 效果策略 | 先及格 → 逐步优化 |
| 互动 | 问答 + 点名 + 表情 + 主动引导（全要） |
| 形象 | 现成 Live2D 模型（面试 demo，授权不纠结） |
| 渲染方案 | 浏览器 Live2D + OBS 浏览器源 |

## 3. 整体架构

```
[B站弹幕 blivedm]──────┐
[本地模拟弹幕(测试)]────┤
                        ▼
              ┌──────────────────┐
              │  编排层 orchestrator │  asyncio 主循环，串起下面所有组件
              └────────┬─────────┘
                       ▼
              ┌──────────────────┐
              │ 互动决策层 policy  │  事件分类 + 优先级 + 冷却 + 循环文案
              └────────┬─────────┘
                       ▼
              ┌──────────────────┐
              │  大脑 brain        │  DeepSeek + RAG(kb.py) → 回复文本 + 情绪
              └────────┬─────────┘
                       ▼
              ┌──────────────────┐
              │  嘴 tts           │  edge-tts → mp3 音频
              └────────┬─────────┘
                       ▼
              ┌──────────────────┐
              │ 浏览器 Live2D 页面 │  WebSocket 收：音频 + 情绪 + 字幕
              │  播放+嘴型+表情+字幕 │  （easy-live2d 渲染 + 嘴型）
              └────────┬─────────┘
                       ▼
               OBS 浏览器源（画面 + 声音）→ 推流 B 站
```

**关键设计点**：音频与嘴型在浏览器内部天然同步——Python 把 mp3 经 WebSocket 发给页面，页面用 Web Audio 播放（声音进 OBS）的同时用 AnalyserNode 分析同一段音频的音量驱动嘴巴。**不需要虚拟声卡，也不存在音画不同步**。

## 4. 组件设计

每个组件单一职责、通过明确接口通信、可独立测试。

### 4.1 弹幕源 `danmaku_source`
- **职责**：连 B 站，把原始弹幕流规整成统一的 `Event` 对象。
- **产出**：`Event(type, user, content)`，`type ∈ {comment(提问), enter(进场), follow(关注), gift(送礼), sc(醒目留言)}`
- **复用**：[blivedm](https://github.com/xfgryujk/blivedm)（web 端接口，无需认证）。测试期可用本地模拟源替换（同一接口）。

### 4.2 互动决策层 `interaction_policy`（核心新增）
- **职责**：决定「现在该说什么、带什么情绪」——这是「主播感」的来源。
- **逻辑**：
  - 优先级：SC > 送礼 > 提问 > 进场 > 关注
  - 冷却：正在说话时不打断，新事件进队列
  - 主动引导：定时/条件触发循环文案（开场白、产品介绍、引导关注）
  - 违禁词过滤（可选，借鉴 AI-Vtuber）
- **输出**：`(要说的文本, 情绪标签)` 或 `None`（暂不响应）
- **借鉴**：[Ikaros-521/AI-Vtuber](https://github.com/Ikaros-521/AI-Vtuber) 的事件分类与循环文案设计；[astrbot 直播插件](https://github.com/menglimi/astrbot_plugin_live_stream_companion) 的「音量包络驱动嘴型」思路。

### 4.3 大脑 `brain`
- **职责**：给定事件/上下文 → 生成口语回复 + 情绪标签。
- **复用**：现有 `kb.py`（RAG 检索知识库防瞎编）+ 扩展 prompt。
- **接口**：`answer(text) -> (reply_text, emotion)`
- **情绪标签**：让 DeepSeek 在回复末尾输出 `[开心] [惊讶] [卖萌] ...` 等标签，供 Live2D 切表情。

### 4.4 嘴 `tts`
- **职责**：文本 → mp3 音频。
- **复用**：现有 `main.py` 的 `speak()`（edge-tts）。

### 4.5 浏览器 Live2D 页面 `live2d_page`（核心新增）
- **职责**：加载模型、播放音频、音量驱动嘴型、按情绪切表情、显示字幕。
- **复用**：[easy-live2d](https://github.com/Panzer-Jack/easy-live2d)（渲染 + `playVoice` 嘴型同步 + `setParameterValueById` 参数控制）。
- **接口**：WebSocket 接收 `{audio: 二进制, emotion: str, subtitle: str}`。

### 4.6 编排层 `orchestrator`
- **职责**：asyncio 主循环，把 4.1→4.5 串成「事件 → 决策 → 生成 → 合成 → 推页面」的流水线。

## 5. 及格版 vs 优化版（阶段边界）

**及格版（第 1 里程碑，能上播）**：
- 问答互动 + 简单点名（欢迎进场 / 感谢关注念 ID）
- 定时主动引导（固定开场白 / 产品介绍脚本）
- 音量驱动张嘴 + 简单表情（默认 + 开心/惊讶两种）
- OBS 推流上播

**优化版（逐步加，每项独立小步）**：
1. 情绪 → 多表情联动
2. 音素级嘴型（替换音量驱动）
3. 送礼 / SC 专项点名
4. 排队优先级细化
5. 换专属角色 Live2D 模型

## 6. 复用 / 借鉴 / 自研对照

| 模块 | 方案 | 复用/自研 |
|---|---|---|
| Live2D 渲染+嘴型 | easy-live2d（pixi.js + Cubism） | ✅ 复用 |
| B 站弹幕 | blivedm | ✅ 复用 |
| 大脑 RAG | kb.py（BGE + ChromaDB） | ✅ 复用（已有） |
| 语音 | edge-tts | ✅ 复用（已有） |
| 互动决策层 | 参考 AI-Vtuber / astrbot 逻辑 | 🔶 自研（组装+借鉴） |
| Live2D 页面 WebSocket 层 | 自写（收音频/情绪/字幕） | 🔶 自研 |

**净效果**：及格版只需自研「互动决策层 + Live2D 页面的 WebSocket 层」两个小件，其余全是组装现成件。

## 7. 已知风险与待处理点

1. **easy-live2d 嘴型同步目前标注仅支持 wav**，而 edge-tts 出 mp3 → 需转 wav（加一步 ffmpeg）或验证 lip-sync 分支是否支持 mp3。**实现第一步先验证此项。**
2. **edge-tts 首字延迟**约 0.3s + 合成时间，叠加 DeepSeek 约 1~2s，预估总延迟 3~6s，达标；但高频弹幕下需冷却/排队策略兜底。
3. **Live2D 模型需在模型内配置 LipSync 参数映射**（如 `ParamMouthOpenY`），选模型时需确认。
4. 现成模型多为 CC BY-NC，面试 demo 可用，**若将来商用需另选可商用模型**。

## 8. 验收标准（及格版）

- [ ] 本地跑通：模拟弹幕 → 数字人开口（嘴型随音量动）→ 浏览器预览可见
- [ ] 接 B 站：真实弹幕能触发回答
- [ ] 点名：进场/关注事件能念 ID 欢迎
- [ ] 表情：情绪标签能切换至少 2 种表情
- [ ] 主动引导：定时触发开场白/产品介绍
- [ ] OBS 浏览器源捕获画面+声音，可推流
- [ ] 端到端延迟 ≤10s，知识库命中不瞎编
