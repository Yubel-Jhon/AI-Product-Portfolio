# easy-live2d 嘴型同步 · 技术风险验证结论

> 日期 2026-08-29 ｜ 对应 spec §7 风险 #1 ｜ 结果：✅ 通过，mp3 无需转 wav

## 结论

**edge-tts 产的 mp3 可以直接喂给 easy-live2d 的 `playVoice` 驱动嘴型，不需要 ffmpeg 转 wav。**

spec 里「easy-live2d 嘴型同步标注仅支持 wav」的说法是**过时/错误信息**，来源是
easy-live2d playground 源码 `HomeView.vue` 里的一行旧注释
`// 当前音嘴同步 仅支持wav格式`（该文件同一处还写了播放网络 mp3 的例子，自相矛盾）。

## 源码证据（easy-live2d v0.4.4）

1. **解码走 Web Audio 原生 `decodeAudioData()`**：
   `packages/core/src/loader/SoundLoader.ts` 的 `loadAudioFile()` 用
   `AudioContext.decodeAudioData(arrayBuffer)` 解码。这个 API 支持浏览器可解码的
   所有格式（wav / mp3 / ogg / aac 等），并非硬编码 wav。

2. **README 明文确认**（`README.md:201` / `README.zh.md:200`）：
   > Voice decoding uses Web Audio `decodeAudioData()`, supporting any
   > browser-decodable audio format (wav, mp3, ogg, etc.).

3. **嘴型链路**（`EffectController.ts`）：
   - `playVoice(voicePath)` → `sound.add('voice', voicePath)`（@pixi/sound 播放，声音进 OBS）
     + `_soundLoader.start(voicePath)`（解码 PCM）
   - 每帧 `updateEffects()`：`lipsync` 时读 `getRms()` → `addParameterValueById(lipSyncId, rms, 3)`
   - `lipSyncId` 来自模型的 `LipSync` 参数组（`setupLipSyncIds`）

4. **Hiyori 模型已配 LipSync**（`Hiyori.model3.json`）：
   ```json
   "Groups": [
     { "Name": "LipSync", "Ids": ["ParamMouthOpenY"] },
     { "Name": "EyeBlink", "Ids": ["ParamEyeLOpen", "ParamEyeROpen"] }
   ]
   ```
   spec §7 风险 #3「模型需配置 LipSync 参数映射」也一并确认满足。

## 运行时验证（Edge headless，端到端）

本地 `live2d_page`（Hiyori 模型 + Cubism Core + edge-tts 现产 `test.mp3`），
浏览器加载后 `playVoice({voicePath:'/test.mp3'})`，轮询读
`sprite._model.effectCtrl.soundLoader.getRms()`，结果：

```
OK mp3 驱动嘴型：RMS 峰值 0.100（>0 即嘴巴随音量开合）
```

RMS 峰值 0.1 = mp3 被 `decodeAudioData` 成功解码，音量包络算出，嘴型参数（ParamMouthOpenY）被驱动。

## 结论对后续开发的影响

- ❌ **不需要** ffmpeg 转 wav 这一步（spec §7 风险 #1 消除）。
- ✅ `tts` 组件照旧用 edge-tts 直接出 mp3，经 WebSocket 二进制发给页面，页面转 blob URL 后喂 `playVoice`。
- ⚠️ 唯一要注意的是：`playVoice` 的 `voicePath` 是**一个 URL**（内部 `fetch` + `@pixi/sound` 都要 URL）。
  所以 WebSocket 收到二进制 mp3 后，页面要用 `URL.createObjectURL(blob)` 转成 blob: URL 再传。
