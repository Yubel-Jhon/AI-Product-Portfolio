## 七、第三步已完成：情绪 → 表情 ✅

`brain` 产出的情绪标签（开心/惊讶/卖萌/平静）现在会驱动 Hiyori 脸部参数切表情：

| 情绪 | 驱动参数（值） | 效果 |
|---|---|---|
| 开心 | ParamEyeLSmile/RSmile=1, ParamCheek=1 | 笑眼 + 脸颊红晕 |
| 惊讶 | ParamBrowLY/RY=0.9, ParamBrowLAngle/RAngle=0.6, ParamMouthForm=0 | 眉毛上挑 + 嘴收平 |
| 卖萌 | ParamEyeLSmile=1/RSmile=0.4(不对称), ParamCheek=0.8 | 单眼眯 + 红晕 |
| 平静 | 全部归位（嘴型回到默认微笑） | 复位 |

关键结论（读 easy-live2d 源码 + 模型文件确认）：
- `sprite.setParameterValueById(id, value, weight)` 是「持久覆盖值，每帧末尾重写」，优先级最高，能压住 idle 动作。
- 覆盖表**没有删除方法**，所以只覆盖 idle 动作里恒为常量的「安全」参数（眉毛/笑眼/脸颊/嘴型），
  **不碰** ParamEyeLOpen(眨眼)/ParamMouthOpenY(唇同步)/ParamAngle*(头部)，否则会永久压死这些自然动画。
- 实测参数范围：ParamBrowLY -1..1、ParamEyeLSmile 0..1、ParamCheek -1..1、ParamMouthForm -2..1，
  `setEmotion` 里已按范围 clamp。
- `weight=0.4` 让切换有平滑过渡（每帧指数逼近）。

**验证表情**：浏览器打开 `http://localhost:8000/?emotion=惊讶`（或 开心/卖萌/平静），
或控制台 `window.__setEmotion('惊讶')`。⚠️ 眉毛「上挑=正数」是按 Live2D 官方约定设的，
若肉眼看方向反了，改 `index.html` 里 `EMOTION_PARAMS` 的符号即可。

## 八、第四步已完成：网页直接输入 ✅（B站已砍）

> 决策：**不接 B 站弹幕了**。demo 版直接改成「网页输入框打字 → 数字人回答」。
> WebSocket 本就是双向的，页面加个输入框发 `{type:'comment', content}`，
> orchestrator 的 `/ws` 收到后塞进同一个决策队列，走和真实弹幕完全一样的优先级/冷却/大脑/嘴。

- `orchestrator.py` 新增 `--web` 模式（`WebSource`，poll 恒空，弹幕全走 /ws）。
- `/ws` 收到 `comment` 消息 → `policy.push(Event("comment","网页",content))`。
- `index.html` 底部加输入框，连上 WS 后显示，回车或点「发送」即发。
- 端到端实测 PASS：网页弹幕 → DeepSeek → edge-tts → WS 回推（收到 speak 元信息 + 26KB mp3）。

剩余（可选，非阻塞）：
1. 点名（进场/关注念 ID）、OBS 推流。

> ⚠️ 已记下的坑（`playVoice` 的 voicePath 必须是个 URL）：页面已用 `createObjectURL` 处理，
> 且「meta text + 二进制 mp3」两条 WS 消息按序配对。OBS 抓 WebGL 加了 `preserveDrawingBuffer: true` 防黑帧。

> ⚠️ 另一个坑（模型缩放，会直接黑屏）：**不能只 `sprite.width = canvas.clientWidth`**——
> easy-live2d 的 width setter 只改 `scale.x`，`scale.y` 不动，模型被拉成「800 宽 × 4175 高」，
> 渲染 viewport 错位 → 整个 canvas 黑屏「没模特」。正确做法是等比缩放 + 居中：
> `fit = min(cw/mw, ch/mh); sprite.scale.set(fit); sprite.position.set((cw-mw*fit)/2, (ch-mh*fit)/2)`。

## 九、第五步：人物放大（上半身占满画面）✅

原来 Hiyori 是全身像，等比缩放塞满画面 → 人物太小。改成放大 2.2 倍、模型顶部对齐画布顶部，
腿部溢出下方被裁掉，头 + 上半身占主视觉。

- `index.html` 抽成 `fitModel(zoom, yBias)`：`scale = fit * zoom`，`y = yBias * 画布高`。
- 默认 `zoom=2.2, y=0`；可调（不用改代码）：
  - URL `?zoom=2.5&y=-0.1`（y 负值 = 整体上移裁头顶留白）
  - 控制台 `window.__fitModel(2.5, -0.1)` 实时调，不用刷新
- 缩放仍是 x/y 同比例（只设 width 会把模型拉变形 → 黑屏）。

## 十一、第七步：TTS 音调微调 + BGE 预热（听感 + 延迟）✅

### TTS 微调（音调/韵律）
- `tts.py` 给 edge-tts 加 `pitch=+25Hz`（音调调高，更像萝莉）、`rate=+8%`（语速调活）。
- 做成环境变量，`.env` 里可加 `TTS_PITCH=+35Hz` / `TTS_RATE=+12%` 微调（pitch 上限 ±100Hz）。
- ⚠️ edge-tts 的「晓晓」本质是少女音，调 pitch 只是变尖、天花板低；要真萝莉得换火山豆包 TTS 或本地 Bert-VITS2。

### BGE 预热（去首答延迟）
- 坑：BGE 向量模型是**惰性加载**，第一条弹幕才第一次加载，卡 ~11s。
- 修：`orchestrator.py` 启动时 `await asyncio.to_thread(kb.get_model)` 预热，把 11s 挪到启动时。
- 实测首答延迟从 11s → **3.7s**（DeepSeek ~2s + edge-tts ~1.2s + 检索 0.01s），符合 ≤10s 目标。
