# v0.3 · 御姐立绘数字人（2D puppet，替换 Hiyori）

> 目标：把 v0.1 的静态全身图，变成「有骨骼感、动态丰富」的御姐形象，替换 v0.2 的 Hiyori（萝莉）。
> 结论：图→Live2D 的自动路走不通（见下），改用 **2D 分层立绘**（原生 Canvas 2D），零构建、零依赖、当天出 demo。

---

## 一、为什么放弃「图→Live2D」自动路

**Live2D Automation MCP Server**（github J621111/live2d-automation）本质是「流程脚手架」，不是「图→模型」生成器。它「导出模型」就两行：

```python
# scripts/native_gui_adapter_demo.py
(output_dir / f"{model_name}.moc3").write_bytes(b"demo-moc3")      # .moc3 = 9 字节假文件
(textures_dir / "texture_00.png").write_bytes(b"demo-texture")     # 贴图也是假字节
```

`.moc3` 内容就是字符串 `demo-moc3`，easy-live2d / Cubism Core 加载必崩。作者自己也标了 `ready_for_cubism_editor=false`。

**结论**：真 Live2D 需 Cubism Editor 人工逐层画绑，没有免费自动工具能「单图出真 moc3」。这是行业常识级限制。

另外两条辅助路也断了（本账号未在火山 Ark 控制台开通）：
- Seedream img2img（生成「闭眼/张嘴」表情变体）→ `404 InvalidEndpointOrModel`
- 豆包视觉模型（定位五官）→ `ModelNotOpen`

---

## 二、方案：2D 立绘 puppet（原生 Canvas 2D）

- **素材**：`src/live2d_page/Resources/OneeSan/body.png`（`正面1.png` 白底→透明，连通域法只切「连边框的白色背景」，保住眼白/高光不被误删）。
- **页面**：`src/live2d_page/oneesan.html`（复用现有 WebSocket/音频/HUD/输入框协议，只换渲染层）。
- **动画**（全程序化，零 AI 漂移）：

| 动画 | 实现 | 参数 |
|---|---|---|
| 呼吸 | scaleY | ±1.2% @0.22Hz |
| 摇摆 | rotate | ±0.7° @0.11Hz |
| 上下微晃 | translate | @0.35Hz |
| 眨眼 | 眼皮贴片下滑（深肤色+睫毛线） | 2.5~6s 一次 |
| 嘴型 | 音频幅度驱动（Web Audio AnalyserNode） | 无分析器时 6Hz 摆动 |
| 情绪 | 开心/卖萌→眯眼，惊讶→嘴张更大 | — |

## 三、关键参数（mediapipe Face Mesh 定位）

- 左眼 (756,813,94×33)、右眼 (982,831,85×24)、嘴 (868,1033,宽175)
- 脸中心 x≈870（≈图中心 864）、**肤色 #665347（褐肌御姐）**、嘴内 #270e08、舌头 #a05a40
- 记录文件：`Resources/OneeSan/face.json`

## 四、运行

```bash
venv/Scripts/python.exe src/orchestrator.py --web --port 8000
```

- 御姐立绘版：`http://localhost:8000/oneesan.html`
- Hiyori 版（v0.2 原样保留）：`http://localhost:8000/index.html` —— 两版并存对比
- 调位置：`?zoom=1.1&y=-0.05`，或控制台 `window.__fitModel(zoom, y)`

## 五、验证结果

- **渲染**：无头浏览器零 JS 报错；canvas 88092 不透明像素铺满画面；眼角/脸颊采样=深褐肤色、角落=透明黑背景。
- **端到端**：WS 连接 → 发评论 → 字幕+情绪出现 → 8.04s 音频在播（`paused=false`）→ 嘴型随音频动。
