
## 三、SadTalker 打通复盘（踩坑与修复）

这条链路是本次最难的部分，共踩 5 个坑，全部解决。

### 坑 1：face_alignment 枚举名变了
- **现象**：`LandmarksType._2D` 报 `AttributeError`
- **原因**：face_alignment 1.3.5 把枚举成员改成了 `TWO_D`，而 SadTalker 官方源码写的 `_2D`
- **修复**：`extract_kp_videos.py` 里 `_2D` → `TWO_D`

### 坑 2：croper.py 依赖 facexlib
- **现象**：`ModuleNotFoundError: No module named 'facexlib'`
- **原因**：`croper.py` 用的是 `extract_kp_videos_safe`（facexlib 版，98 点 + RetinaFace），而 facexlib 没装
- **修复**：切到 face_alignment 版 `extract_kp_videos`，`get_landmark` 重写为 `detector.get_landmarks_from_image()`（直接返回 68 点、全图坐标）。备份 `croper.py.bak.facexlib`

### 坑 3：gfpgan 顶层 import 炸
- **现象**：`from gfpgan import GFPGANer` 报错
- **原因**：`animate.py` 无条件 import `face_enhancer`，后者顶层 import gfpgan。虽然 `--enhancer None` 不会真调用（`if enhancer:` 才用），但 import 阶段就挂
- **修复**：`face_enhancer.py` 里 gfpgan import 包成 try/except（GFPGANer=None）。**没装 gfpgan**，因为根本用不到

### 坑 4：answer.wav 其实是 MP3
- **现象**：`wave` 模块报 `file does not start with RIFF id`
- **原因**：edge-tts 输出的是 MP3 流，被存成了 `.wav` 后缀
- **处理**：实测 `librosa.load`（soundfile 1.2.2）能按内容嗅探读 MP3，**无需转换**，直接用

### 坑 5：混音缺 ffmpeg/ffprobe
- **现象**：走到 99%（Face Renderer 102/102 全跑完），`FileNotFoundError: ffprobe`
- **原因**：`pydub` 读音频要 ffprobe，`paste_pic`/`save_video_with_watermark` 要 ffmpeg 子进程
- **修复**：`apt-get install -y ffmpeg`（连 ffprobe 一起，覆盖所有子进程调用）

### 关键决策：mapping 权重用哪个
- `init_path.py` 逻辑：**`full` 模式用 `mapping_00109`，`crop` 模式用 `mapping_00229`**
- 半身像的正确姿势是 `--preprocess full --still`（保留整张半身、只动嘴），正好用已下好的 00109，**省掉下载 00229**

## 八、v0.2 · Live2D 浏览器方案（实时化，已出可演示 demo）

> v0.1 的 SadTalker 太慢（8s 音频 ≈ 90s 推理），没法实时直播。v0.2 换浏览器 Live2D 方案：
> CPU 实时渲染，复用 v0.1 的脑（DeepSeek + RAG）和嘴（edge-tts），只自研两块——
> 「互动决策层」+「Live2D 页面 WebSocket 层」。详细步骤见 `v0.2_搭建步骤.md`。

### 架构

```
弹幕 ─► orchestrator(单进程) ─► 决策(优先级+冷却+主动引导) ─► 脑(DeepSeek+RAG) ─► 嘴(edge-tts mp3)
                                       │
                              WebSocket(text meta + binary mp3)
                                       ▼
                        浏览器 Live2D(pixi.js + easy-live2d) ─► 开口 + 字幕 + 表情
```

### 已完成（8 步全通，可演示的完整 demo）

1. ✅ 嘴型同步：edge-tts 的 mp3 直接喂 easy-live2d，无需转 wav
2. ✅ WebSocket 实时闭环 + orchestrator（一条命令起：静态页 + /ws + 主循环）
3. ✅ 情绪 → 表情：开心/惊讶/卖萌/平静 → 脸部参数切表情
4. ✅ 网页直接输入：不接 B 站，页面输入框打字喂数字人（`--web`）
5. ✅ 人物放大：Hiyori 放大 2.2 倍，上半身占满画面
6. ✅ 语料人设化：人设「小七」+ 事实锁死表达自由，faq 扩到 18 条，不再照抄
7. ✅ TTS 微调：pitch +25Hz / rate +8%，音调更高语速更活
8. ✅ BGE 预热：启动时加载向量模型，首答从 11s 降到 3.7s

### 踩坑（4 个，全解决）

1. **CDN 依赖 → 黑屏**：jsdelivr 被系统代理（10809）卡死 → 用 esbuild 把
   `pixi.js + easy-live2d + @pixi/sound` 打包成本地单文件 `vendor/live2d.bundle.mjs`，页面不碰外网。
2. **AudioContext 自动播放被拦（无声）**：加「点击开始直播」遮罩，在用户手势里 resume 音频。
3. **DeepSeek 走系统代理超时 → 服务器崩**：openai 的 httpx 会读 WinINET 代理（127.0.0.1:10809）
   → `trust_env=False` 直连；orchestrator 的 `say()` 出错降级不崩。
4. **模型缩放 → 全黑（最关键）**：只 `sprite.width = ...` 只改 `scale.x`，`scale.y` 不变，
   模型被拉成 800×4175、渲染 viewport 错位 → 全黑「没模特」。必须**等比缩放 + 居中**
   `sprite.scale.set(fit)`（实测 canvas 非黑像素从 0 → 21491）。
5. **BGE 惰性加载 → 首答卡 11s**：向量模型第一次检索才加载（惰性），首答延迟 11s。
   修：orchestrator 启动时 `to_thread(kb.get_model)` 预热，首答降到 3.7s。
